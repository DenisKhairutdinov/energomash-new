# Основа будущих карточек каталога

`semitrailers.json` содержит полуприцепы-цистерны, сгруппированные по назначению,
объёму и количеству секций, включая вакуумные. Источник — все соответствующие
позиции `public/data/catalog.json`, включая складские исполнения.

- `categories`: назначения с отдельными списками карточек. `grouping` равен
  `volume-sections` для всех категорий.
- `designation`: обозначение группы, например `16/1` или `16/2`.
- `volume`: объём в м³; `sections`: количество секций. Определяются по `model`:
  число секций идёт после `/`, отсутствие `/` означает одну секцию. Суффиксы
  `Т`, `К`, `ТК` не образуют дополнительные карточки.
- `availableSsuMm`: уникальные доступные высоты ССУ в мм именно для этой группы,
  по возрастанию. Источник — `params.ssu`, без переноса значений из других групп.
- `photos`: уникальные имена фотографий исходных модификаций и их складских единиц.
  Копии находятся в `src/assets/catalog-cards/<id карточки>/`.
- `sourceItems`: исходные модификации (`id`, обозначение `model`, код исполнения
  `code`, высота `ssuMm`). `ssuMm: null` означает, что характеристика не указана;
  такие позиции не добавляют значений в `availableSsuMm`.
- У вакуумных `sourceItems` дополнительно содержит `params`: исходные
  характеристики исполнения, включая насос и подвеску.
- `source.sourceItemsWithoutSsu`: список исходных позиций без указанного ССУ.
- `briefCharacteristics`: блок «Краткие характеристики» для светлых нефтепродуктов.
- `optionalEquipment`: блок «Возможные опции» для светлых нефтепродуктов.

Общие характеристики и опции редактируются в `characteristics.json`.
Количество осей подставляется в каждую карточку по её объёму из `params.axles`
исходных моделей той же категории. Пустой `values` и `status: needs-confirmation`
означают, что данных нет. Подтверждённые значения можно задать в
`semitrailerCharacteristics.fuel.axleCountsByVolume`, например `"16": [2]`.
Эти значения имеют приоритет над исходным каталогом. Общие варианты характеристик
не утверждают совместимость любых опций между собой.

Для светлых нефтепродуктов подтверждено: ниже 20 м³ — только 2 оси;
начиная с 20 м³ доступно 3 оси. У объёмов 20 и 24 м³ сохранён также вариант
с 2 осями, присутствующий в исходном каталоге.

Данные подготовлены для будущего объединения; текущие карточки сайта продолжают
использовать исходный каталог.
Вопрос разделения рамных и безрамных исполнений остаётся открытым.

[Таблица карточек](semitrailers-table.md) создаётся из тех же данных. Вакуумные
показаны отдельным разделом с теми же колонками, что и остальные категории.
Различия насосов, подвесок и исполнений с открывающимся днищем (`ОД`) сохранены
в исходных модификациях внутри группы и не создают дополнительных карточек.

Пересоздать JSON и Markdown-таблицу после изменения исходного каталога:

```sh
node scripts/build-semitrailer-cards.mjs
```

Генератор проверяет совпадение объёма и секций с характеристиками, полноту
покрытия исходных позиций и отсутствие дублей. Ручные изменения JSON при
повторной генерации перезаписываются.

Полные характеристики задаются в `full-characteristics.json` по назначению
или по ID отдельной карточки (он имеет приоритет над общим шаблоном).
Шаблон `fuel` применяется ко всем 32 карточкам для светлых нефтепродуктов.
`briefId` подставляет все варианты из кратких характеристик, `valueLabels`
расшифровывает их; `field` берёт объём, секции и доступные высоты ССУ карточки.
Количество горловин равно количеству секций и подставляется из `sections`.
Сведения о рамной конструкции относятся только к рамному исполнению.

`npm run product:documents` обновляет карточки и создаёт настоящие `.docx`
в `public/downloads/` из тех же данных, что отображаются на странице.
Команда включена в сборку сайта. Документ содержит все варианты и опции модели.

В DOCX на каждой странице повторяются шапка с логотипом и описанием завода,
а также подвал с реквизитами, контактами, QR-кодом на `site.url` и номером страницы.
Название, регистрационные реквизиты и контакты берутся из `home.json`,
сайт — из `site.json`, описание, адрес и банковские данные — из
`src/data/document-branding.json` (данные страницы реквизитов).
Логотип для Word — `src/assets/documents/logo.png`, PNG-копия
`src/assets/images/logo.svg`. При изменении логотипа обновляется и PNG-копия.
QR-код генерируется локально библиотекой `qrcode`, без внешних сервисов.
